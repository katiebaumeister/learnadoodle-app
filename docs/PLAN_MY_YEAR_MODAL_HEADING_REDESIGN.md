# Plan My Year Modal — Heading & Layout Redesign Spec

Visual hierarchy and layout spec so the modal reads as **capacity infrastructure**, not curriculum. Copy comes from **curriculumPlanningCopy.json** (`planMyYear.*`). No behavior changes—only layout and labeling.

---

## 1. Header block

| Element | Copy (from JSON) | Notes |
|--------|-------------------|--------|
| **Title** | `planMyYear.modal.title` → **Plan My Year** | Primary heading |
| **Subtitle** | `planMyYear.modal.subtitle` → **Set when learning can happen and how much time is required.** | One line under title |
| **Helper** | `planMyYear.modal.helper` → **This creates instructional slots on the calendar. Fill slots with lessons later.** | Smaller, muted; clarifies “slots” not “lessons” |

**Visual hierarchy:** Title largest, subtitle secondary, helper tertiary (smaller type, muted color).

---

## 2. Top-right action cluster

Keep consistent with app tone:

| Control | Label (from JSON) | Behavior |
|--------|--------------------|----------|
| **Secondary** | `global.actions.close` → **Close** | Dismiss modal |
| **Primary** | `planMyYear.primaryActions.generateSlots` → **Generate instructional slots** | Disabled until plan is valid (dates + at least one block, etc.); on edit/reapply use **Update instructional slots** where appropriate |

---

## 3. Section ordering

Use this order (left-to-right or top-to-bottom depending on layout):

1. **Dates** — `planMyYear.sections.dates`
2. **Weekly blocks** — `planMyYear.sections.blocks`
3. **Breaks & holidays** — `planMyYear.sections.breaks`
4. **Targets (optional)** — `planMyYear.sections.targets`
5. **Preview** — `planMyYear.sections.preview`

Section titles/subtitles and empty states use the keys under `planMyYear.sections.*` in the JSON.

---

## 4. Preview card styling

Preview should read as a **read-only computation panel**, not as curriculum content.

| Element | Copy (from JSON) |
|--------|-------------------|
| **Heading** | `planMyYear.sections.preview.title` → **Preview** |
| **Subtext** | `planMyYear.sections.preview.subtitle` → **Estimated instructional time based on your blocks and exclusions.** |
| **Metrics rows** | `planMyYear.sections.preview.labels.estimatedSlots`, `estimatedDays`, `estimatedHours` → **Estimated slots**, **Estimated instructional days**, **Estimated instructional hours** |
| **Button (secondary)** | `planMyYear.sections.preview.actions.computePotential` → **Update preview** |
| **Button (conditional)** | `planMyYear.sections.preview.actions.recalculate` → **Recalculate** — show only when constraint solver is active (e.g. target days/hours set) |

**Styling:** Card or panel with subtle background; metrics in a simple grid or list; secondary button style for “Update preview”.

---

## 5. Apply confirmation modal

When user clicks **Generate instructional slots** / **Update instructional slots** and the plan already has filled slots (or reapply case), show confirmation:

| Element | Copy (from JSON) |
|--------|-------------------|
| **Title** | `planMyYear.confirmations.replaceEmptySlots.title` → **Update instructional slots?** |
| **Body** | `planMyYear.confirmations.replaceEmptySlots.body` → **This will update only empty instructional slots generated by this plan. Scheduled lessons will not be changed.** |
| **Confirm** | `planMyYear.confirmations.replaceEmptySlots.confirm` → **Update empty slots** |
| **Cancel** | `planMyYear.confirmations.replaceEmptySlots.cancel` → **Cancel** |

---

## 6. Success toasts

After apply completes:

| Scenario | Copy (from JSON) |
|----------|-------------------|
| **First-time generate** | `planMyYear.toasts.generatedWithCounts` → **Generated {count} instructional slots.** (interpolate `count`) |
| **Reapply / update** | `planMyYear.toasts.updatedWithCounts` → **Updated {updated} slots, added {inserted}, removed {deleted}.** (interpolate counts) |
| **Optional follow-up** | `planMyYear.toasts.skippedFilled` → **Scheduled lessons were kept unchanged.** (e.g. when any filled slots existed) |

Use `planMyYear.toasts.generated` / `planMyYear.toasts.updated` if no counts are available.

---

## 7. JSON key reference (Plan My Year)

All strings above live in **`lib/constants/curriculumPlanningCopy.json`** under `planMyYear`:

- `modal.title`, `modal.subtitle`, `modal.helper`
- `sections.who`, `sections.subjects`, `sections.blocks`, `sections.dates`, `sections.targets`, `sections.breaks`, `sections.preview` (each with `title`, `subtitle`, and section-specific `labels` / `actions` / `empty`)
- `primaryActions.generateSlots`, `primaryActions.updateSlots`, etc.
- `confirmations.replaceEmptySlots.*`
- `toasts.*`
- `calendar.*` (slot badges and tooltips for calendar view)

Implementations should import the JSON and use these keys so copy stays aligned with the UI Language Spec and the constants file remains the single source of truth.
